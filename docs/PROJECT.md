# Project brief — Khata-to-Credit (AICON'26 · Build With AI)

> Status: **active** — idea and stack chosen by the human lead on 2026-10-09.
> Team: **TEAM Uswa and Mutahar** · Domain: **Financial Operations**

## One-liner
Turn a shopkeeper's handwritten *khata* (credit ledger) into an explainable
credit-readiness score that a microfinance loan officer can trust — from a single
phone photo.

## Problem
Small shopkeepers (kiryana stores, vendors, home businesses) run their business
on a paper khata: daily sales, stock purchases and *udhaar* (credit given to
customers). Because none of this is digital, they have no formal financial
record, so banks and microfinance lenders can't assess them. They are
"credit-invisible": refused, or pushed to informal lenders at high cost.

On the lender side, field officers assess these borrowers manually by flipping
through notebooks — slow, inconsistent and hard to audit.

## Solution
A web app where a shopkeeper (or loan officer) photographs khata pages and gets:

1. **Digitised ledger** — every entry extracted into a table (date, description,
   type, amount), editable before analysis.
2. **Cash-flow profile** — monthly inflow/outflow, margin, volatility, udhaar
   exposure and recovery rate.
3. **Credit-readiness score (0–100)** with a band (Ready / Building / Not yet),
   a suggested safe loan size and affordable monthly instalment.
4. **Plain-language explanation** in English and Urdu: the top factors pushing
   the score up and down, and 3 concrete steps to improve it.
5. **Integrity flags** — unusual entries and page totals that don't add up.

## Pipeline (judging flow: Problem → Data → AI → Solution → Impact)

| Stage | What happens | AI? |
|-------|--------------|-----|
| Input | Photo(s) of khata pages, or a CSV, or a built-in sample | — |
| 1. Extraction | Vision LLM reads handwritten Urdu/English/Roman-Urdu entries into structured JSON (schema-constrained) | **Gemini vision** |
| 2. Validation | Arithmetic checks on page totals, outlier detection on amounts | Statistical (robust z-score) |
| 3. Features | ~10 cash-flow features (inflow level, volatility, margin, udhaar ratio, recovery rate, active days, trend, history length) | — |
| 4. Scoring | Logistic-regression model trained on a synthetic population of shop profiles; per-feature contributions are exact, so every score is explainable | **ML model** |
| 5. Explanation | LLM turns the numeric factors into a short explanation + improvement plan in English and Urdu, grounded only in the computed numbers | **Gemini text** |
| Output | Dashboard for the shopkeeper / loan officer | — |

Why this is more than "a chatbot on top": the LLM does perception (handwriting →
data) and communication; the decision itself is a separate, transparent ML model
whose reasoning can be inspected factor by factor.

## Data (rulebook: public, synthetic, anonymised or authorised only)
- **Synthetic** shop population generated by `apps/api/app/ml/synthetic.py`
  (assumptions documented in the code) to train the scoring model.
- **Sample khata pages** written by the team with made-up names and amounts for
  the demo. No real personal or financial data is used.
- We state this openly in the demo: the model shows the method; a lender would
  retrain it on its own repayment outcomes.
